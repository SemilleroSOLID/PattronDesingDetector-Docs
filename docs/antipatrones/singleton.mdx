# Singleton

Detecta si una clase **ya implementa** el patrón Singleton, o si es
**candidata** a implementarlo por cómo se usa en el resto del proyecto.

## Evidencia de que ya está implementado (`detected`)

Una clase se marca como `detected` si tiene la forma clásica del patrón:

- Constructor **privado**
- Campo **estático** que guarda la instancia
- Método **estático** de acceso a esa instancia

También se reconocen dos variantes no clásicas, cualquiera de las dos marca
`detected` igual que la forma clásica:

| Variante | Forma |
|---|---|
| `enum` | `public enum X { INSTANCE; }` |
| `eager_static` | `static final X INSTANCE = new X();` sin *lazy-loading* |

Cuando hay más de una variante presente a la vez, se prioriza en este orden:
`enum` > `eager_static` > `classic`.

## Evidencia de que es candidata (`potential`)

Si la clase **no** implementa el patrón, se marca como candidata cuando
cumple alguna de estas condiciones — y además tiene al menos un método o un
atributo (para no marcar clases vacías):

- Tiene **estado compartido**: campos estáticos mutables, o campos de
  instancia que terminan compartiéndose entre múltiples usos.
- Tiene **configuración de acceso único**: el patrón típico de una clase de
  configuración global.
- Se **crean múltiples instancias** en el proyecto de una clase que, por
  cómo se usa en el resto del código, debería ser única.

## Conflicto multi-antipatrón

Singleton **no participa** del conflicto multi-antipatrón: no cuenta para el
umbral de dos antipatrones, no genera tarjeta de conflicto y no consume una
llamada de prioridad de IA.

- Si el patrón **ya está implementado** (`detected`), es una buena noticia y no
  compite por el refactor. Una clase con God Class y un Singleton bien
  implementado sigue teniendo un solo antipatrón en conflicto (God Class).
- Si la clase es solo **candidata** (`potential`), tampoco entra al conflicto.
  Cuando además tiene God Class o SRP sin resolver, la sugerencia se pospone
  hasta que la clase se reestructure.

## Sugerencia de IA

Cuando la clase es candidata (`potential = true` y no `detected`), el
backend le pide a un modelo de IA una sugerencia concreta de implementación.
La sugerencia se pospone (`suggestionPostponed = true`, sin sugerencia
todavía) si la misma clase tiene una violación estructural sin resolver (God
Class o SRP): implementar Singleton sobre una clase que además hay que dividir
sería prematuro.
