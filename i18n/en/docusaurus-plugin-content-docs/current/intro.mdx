# Introduction

**Pattern Detector** is the project of the **SOLID** student research team
(Universidad de Caldas): a Python backend and a VS Code extension that
analyze Java projects to detect **design patterns** and, additionally,
violations of the **SOLID** principles and other bad practices.

## Main focus: creational patterns

The tool's core goal is to identify **candidates** for three creational
patterns — classes where the pattern would fit, even if the code doesn't
implement it yet:

- **[Singleton](./antipatrones/singleton)** — shared state, single-access
  configuration, or multiple instances of a class that's used as if it
  were unique.
- **[Factory Method](./antipatrones/factory-method)** — interfaces with
  several implementations and direct instantiation points (`new`) spread
  across the code.
- **[Builder](./antipatrones/builder)** — classes with fluent methods
  (`return this`) that don't have a `build()` method yet.

When a class **already implements** the pattern, the tool also recognizes
that (`detected`) instead of suggesting something that already exists.

## Additional detection: SOLID principles

Besides the creational patterns, the backend flags:

- **[God Class](./antipatrones/god-class)** — too many methods or
  attributes for a single class.
- **[SRP](./antipatrones/srp)** — too many methods **and** too many
  distinct imports at the same time.
- **[DIP](./antipatrones/dip)** — too many concrete dependencies
  instantiated directly with `new`.
- **[OCP](./antipatrones/ocp)** — too many `instanceof` branches or
  `switch` cases that should be resolved with polymorphism.
- **[LSP](./antipatrones/lsp)** — overrides that can't substitute their
  base method without breaking the contract.

All with configurable thresholds, not rigid rules. When the same class
triggers two or more of these violations at once, the tool doesn't
generate a suggestion blindly: it asks an AI model which one is worth
tackling first, and the user chooses.

## How it's put together

- **Backend** (Python / FastAPI): receives the Java code, parses it with
  tree-sitter, runs the detectors, and — when applicable — generates an
  AI refactor suggestion, verified by a second QA agent before delivering
  it.
- **VS Code extension** (TypeScript): captures the project's Java files,
  calls the backend, and shows the results in a findings tree and a
  Markdown report — without leaving the editor.

The two repos are independent, private, and communicate only over HTTP —
see [Architecture](./arquitectura) for the detail of how they fit together.
