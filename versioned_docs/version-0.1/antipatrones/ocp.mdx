# OCP (abierto/cerrado)

Detecta señales de que una clase no está "cerrada a modificación": agregar
un nuevo caso obliga a tocar el código existente en vez de extenderlo.

## Señales

- **Ramas `instanceof`**: cadenas de `if/else` que preguntan el tipo
  concreto de un objeto para decidir qué hacer.
- **Casos `switch`**: un `switch` sobre un campo tipo "tag" que decide
  comportamiento distinto por caso.

## Regla

Se marca la clase si supera **cualquiera** de los dos umbrales (default: 3
ramas `instanceof`, 4 casos `switch` — es "O", no "Y"):

```
instanceof_branches > 3  O  switch_cases > 4
```

La advertencia incluye la lista completa de ramas que dispararon la alerta,
ordenadas por línea, con el tipo de cada una (`instanceof` o
`switch_case`).

## Sin sugerencia de IA

Igual que DIP, esta heurística no genera una sugerencia de refactor por
IA — no hay un umbral numérico que se preste a una propuesta de código
concreta (el refactor típico, introducir polimorfismo, requiere rediseñar
la jerarquía de tipos, no es un cambio mecánico). La advertencia señala
dónde está el problema; la decisión de diseño queda en manos del
desarrollador.
